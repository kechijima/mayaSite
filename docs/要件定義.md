# 有料会員限定コンテンツ配信システム 要件定義書

## 1. システム概要
本システムは、ニュース記事やコラムなどのコンテンツを配信するWebサイトである。コンテンツは「無料部分」と「有料会員限定部分」に分かれており、ユーザーは月額サブスクリプション（課金）を契約することで、全てのコンテンツを閲覧可能となる。

### 1.1 開発スタック
* **フロントエンド / サーバー:** Nuxt 3 (SSR/BFF構成), Tailwind CSS
* **認証 / データベース:** Firebase Authentication, Cloud Firestore
* **決済インフラ:** Stripe (Stripe Billing / Stripe Checkout)

---

## 2. 業務・システム全体フロー
1. **コンテンツ登録（管理者）:** 管理者が管理画面から記事（無料エリア・有料エリア）を投稿する。
2. **閲覧（一般ユーザー）:** 非会員・無料会員は記事の無料エリアのみ閲覧可能。ペイウォール（課金導線）が表示される。
3. **課金（一般ユーザー）:** Stripeを介してサブスクリプションを契約する。
4. **ステータス同期:** Stripeの決済完了イベント（Webhook）をNuxtサーバーが検知し、Firebase上のユーザーに「有料会員フラグ」を付与する。
5. **全文閲覧:** 有料会員がログインすると、API側で認証・認可が行われ、記事の全文が配信される。

## 4. 非機能要件（セキュリティ・データ設計）

### 4.1 セキュリティ・データ保護（ペイウォール）
* **APIによる認可制御:** 記事データの取得は必ずNuxtのServer Routes（`/server/api/article/[id].ts`）を経由する。クライアントから送られたFirebase IDトークンをサーバー側（Firebase Admin SDK）で検証し、有料会員でなければ「有料エリア本文」のデータをレスポンスに含めない。**（フロントエンドのCSSによる非表示は不可）**
* **管理画面のアクセス制限:**
  管理画面（`/admin/**`）へのアクセスは、Firebase Authの「カスタムクレーム（Custom Claims）」機能等を用いて、`admin: true` の属性を持つユーザーのみにNuxtのミドルウェア（Middleware）で厳格に制限する。
